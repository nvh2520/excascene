# Release-only compatibility and provenance

Scientific generator, fault, model, training, selector and analysis code is copied without refactoring. `source_hashes.csv` records the released bytes. The BEVFusion compatibility header retains the evaluated Tensor scalar-type adaptation; its added Apache modification notice leaves its scientific body unchanged. The patch is against the recorded upstream commit.

Thin tools bind the deposit into the original layout, replay the frozen latent functions, reconstruct three requested tables, compile the unchanged native build script and run the unchanged fixture harness. The fixture wrapper substitutes a release-scoped verifier for a historical full-private-tree verifier: all supplied source hashes, the original protocol digest, both fixture checkpoint locks, the gate lock and newly built binary hashes are checked. New binaries are not represented as byte-identical to the old binaries. Administrative files excluded from the public package are not represented as reproduced.

The supplied kit's `build_zenodo_deposit.py` is unchanged for plan and pack. Its repository copy adds an explicit `finalize --defer-placeholders` argument for the author-owned fields authorized in this private preparation. Deferred fields remain visible and are printed in the receipt. The original kit is preserved; publication must run finalize and audits without deferral. No audit detection rule is weakened.

Original and corrected scientific exports are preserved separately. Existing historical receipts that embed workstation paths are acknowledged rather than edited. The original fixture harness contains its old runtime description; the new `fresh_installation_context.json` and compilation receipt describe the actual release test.

The native build wrapper also places the fresh environment bin directory on PATH and quotes PyTorch-generated linker search paths for checkouts containing spaces. This is shell argument handling; it does not change operator source or numerical compiler flags.
